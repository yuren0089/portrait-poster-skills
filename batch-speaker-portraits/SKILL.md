# 批量人物照片精修与交付

将一组人物照片处理为可排版的半身透明素材。用户本次规格优先；未另行指定时，采用 1200×1200 px、144 dpi、透明 PNG、腰部附近的半身构图，头顶至下巴高度约占画面高度 1/3（约400 px）。向用户说明此比例按高度计，不是脸部面积或头部宽度。已有明确口径时不重复询问。

## 原图与文件名绑定

- 先盘点用户指定的原图目录。排除成品、待检、返工、隐藏目录及预览图，禁止把上轮生成物重新当原图。
- 处理前建立持久清单：原图相对路径、SHA256、指定输出相对路径、生成结果实际路径、处理状态。输出沿用原图完整文件名和目录，仅扩展名改为 `.png`；遇到同目录同名不同扩展名，先解决输出冲突，不覆盖。
- 每次生成、保存、检查都使用同一条清单记录。不可根据目录枚举顺序、展示顺序或记忆给结果命名。记录工具返回的实际生成路径，不猜最新文件。
- 姓名以用户提供的原图文件名为准；核对的是来源和人物视觉对应，不声称已验证真实身份。
- 保留原图。生成图先落入待检目录，验收后才进入正式目录。保存状态以便中断后继续，不用重做已通过的图。

## 处理

使用当前环境的内置图像生成/编辑工具；需要具体调用时遵循可用的 imagegen 技能。每个人单独编辑，只引用该人的正确原图。先查看原图（大文件可看等比缩略图），再调用编辑工具。要求真实透明背景，而不是白底或棋盘格图案。

优先保留原图已有信息：五官比例、年龄、肤色、表情、发型、眼镜、服装、拍摄角度和姿势。已有半身照主要去背景与调整构图；头像只补全缺失身体。低清修复保守处理，不美颜、瘦脸或虚构可辨识特征。胸牌、话筒、衣物标识不要擅自清空；无法恢复的小字不承诺准确还原。

生成提示词与检查记录字段见 [references/workflow.md](references/workflow.md)。生成失败可重试一次；持续失败保存进度并明确未完成项，不改用未获授权的付费 API。不要把生成预览称为交付完成。

## 确定性导出

生成工具可能忽略尺寸和 DPI，必须以最终文件读取结果为准。生成后单独进行等比缩放、透明画布排版及 DPI 写入，不拉伸脸部。

macOS 可使用 `scripts/normalize.swift`，输入人工查看生成图后定位的头顶与下巴像素 y 坐标（从上向下），自动将头部高度校正到目标比例。脚本只负责几何及文件参数，不负责修复、抠图或判定人物相似度。

```sh
swift scripts/normalize.swift INPUT.png STAGING.png TOP_Y CHIN_Y 1200 144 0.3333333333
python3 scripts/audit.py STAGING.png --size 1200 --dpi 144
```

依赖：macOS AppKit；文件检查需 Python 3 + Pillow。非 macOS 使用环境可用的等价确定性工具；不要假定 Swift 能运行。几何处理必须等待完成后再读取结果，不能在编译尚未完成时运行旧程序。

## 每张交付门槛

1. **对应关系**：输入路径、原图哈希、生成路径、输出姓名及专场一致；视觉对照没有串人。
2. **脸部保真**：逐张对照原图检查眼睛、鼻子、嘴型、脸型、发际线、表情和眼镜。生成细节不等于恢复出的真实细节；不要承诺像素级保真。
3. **构图**：完整头顶与肩部、自然半身到腰附近、手臂无明显畸形。缩放校正后必须重新查看，不能裁掉头发来凑比例。
4. **头部比例**：记录实际最终图中头顶与下巴位置及比值；默认目标约400 px，可按约±20 px人工定位误差验收。不能仅凭提示词或缩放公式声称已测量通过。用户要求更严格时按其标准执行。
5. **文件参数**：实际1200×1200、PNG、DPI约144、存在全透明和不透明像素。PNG的像素/米整数存储会产生微小DPI舍入差异，容许0.02 dpi。
6. **透明边缘**：在浅色和深色底上查看，检查白边、残背景、头发缺失及衣服透明破洞。仅有Alpha通道不代表抠图合格。

失败的图保留在待检/返工目录并标明原因；返工后重新检查相关项。文件参数通过不自动等于视觉通过，脚本不得自动填“脸部通过”。

## 整批交付

按清单逐张验收，所有要求完成前不提前结束。最终核对人数、目录、文件名、漏项、重复项和原图未改动。交付正式PNG目录、压缩包、逐张检查记录；需要用户快速看效果时提供原图/成品对照页。压缩包只放通过的成品和记录，验证文件数量和压缩包完整性。若仍有阻塞明确实际完成数及未通过原因，不包装成全量完成。
